# Data dictionary

All timestamps are `timestamptz` and API deadlines must include a timezone. UUIDs are generated by PostgreSQL; event IDs are monotonic bigints.

| Table | Keys and main columns | Relationship and constraint |
| --- | --- | --- |
| `organizations` | PK `id`; unique `name`; `share_inventory`, `active` | Supplier sharing is explicit |
| `users` | PK `id`; unique lowercase `email`; Argon2id `password_hash`; `active`, `platform_admin` | Accounts may belong to several organizations |
| `memberships` | PK `(user_id, organization_id)`; `role`, `active` | Five organization roles; active membership required |
| `sessions` | PK `id`; unique `token_hash`; `csrf_hash`, expiry, revocation | FK user; server-side revocation |
| `locations` | PK `id`; unique `(id, organization_id)` and `(organization_id,name)`; kind, contact, capacity, geography point | FK organization; valid WGS84 position |
| `resources` | PK `id`; unique `(name,unit)`; category, unit, active | Unit whitelist; shared catalog |
| `inventory_lots` | PK `id`; FK location/org and resource; unique `(org,resource,lot_code)`; expiry, on_hand, reserved | Exact numeric; 0 ≤ reserved ≤ on_hand |
| `inventory_movements` | PK `id`; FK lot/actor; delta, reason | Nonzero delta; append-only by API contract |
| `resource_requests` | PK `id`; FK org/delivery location/creator; priority, status, deadline, reason | Status and priority checks |
| `request_items` | PK `id`; unique `(request_id,resource_id)`; quantity | Positive quantity per resource |
| `match_candidates` | PK `(request_item_id,lot_id)`; score components JSONB, total, distance, generation time | Recommendation snapshots, not reservations |
| `allocations` | PK `id`; unique `(request_item_id,lot_id)`; quantity, creator | Positive quantity; row-locked reservation |
| `shipments` | PK `id`; unique allocation and reference; status, milestone times, recipient name, evidence note | One shipment per allocation |
| `status_events` | Identity PK; FK request/actor; old/new status, time | Append-oriented transition history; null actor for system expiration |
| `idempotency_keys` | PK `(actor_id,scope,key)`; input digest, response JSONB | Advisory transaction lock serializes key reuse |
| `rate_limits` | PK hashed bucket; window, attempts | 15-minute login/registration limiter |
| `audit_events` | Identity PK; FK org/actor; action, entity, relevant states JSONB, correlation ID, time | Trigger rejects update/delete; app role has no update/delete |

JSONB stores flexible diffs and response snapshots, not relational entities. The code does not create materialized views, partitions or row-level security because bounded queries and explicit tenancy checks meet the current prototype scope; revisit with measured workloads and a reviewed database policy.
