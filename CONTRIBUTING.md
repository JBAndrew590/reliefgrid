# Contributing

Use professional English for code, UI and documentation. Open an issue describing the user problem before large changes. Create a branch, add behavior-focused tests, and run `make test`, `make lint`, `make typecheck` and `make build` before submitting a pull request. For database changes, add an Alembic revision, document invariants and demonstrate a migration round trip. Use Conventional Commits, such as `fix(api): preserve reserved stock on adjustment`. Never commit real beneficiary data, credentials or private keys.
